FINAL · 通知配对模型

开锁后没收到关锁通知，50 分钟时提醒

美团单车的开锁与关锁各推一条通知。整个判定就是一次配对：只收到前一条、等不到后一条，就是忘记了。

只监听通知 不需要 root 正常骑行全程静默 T+50 min 兜底

01判定模型

实测的两条推送：

美团
开锁成功，正在骑行中 🚲
点击返回App查看订单信息，快速关锁还车~
美团
行程结束，已为您关锁结费
您已成功关锁还车，点此查看行程费。

所以状态机只有两个动作：

  • 收到开锁通知 → 建立会话，起 50 分钟倒计时
  • 收到关锁通知 → 撤销倒计时，回到静默
这个模型的好处是「不打扰」

绝大多数骑行在 10–30 分钟内结束，关锁通知一到倒计时就撤了，全程没有任何提示音、没有任何通知。这类工具最容易死在「太吵」上——只有异常时才出声，才可能长期留在手机里。

02为什么是 50 分钟

平台在车辆连续静止 60 分钟时自动结束订单并停止计费。定在 50 分钟，留出 10 分钟处置窗口：发现、折返、上锁、或者联系客服，都还来得及。

如果设在 60 分钟之后就没有意义了——那时订单已经被平台关掉，你能做的只剩申诉。

时点动作
T+50 minL1：高优通知 + 强震动 + 语音播报
T+55 minL2：追加全屏界面 + 响铃
T+60 minL3：最长震动，语音改为警告
超过 60 min停止，平台已自动结单

03解析规则里的三个坑

这两条文案看起来干净，但直接写正则会踩三个坑，其中前两个都会让方案彻底失效。

坑一：开锁标题里带「骑行中」

开锁成功，正在骑行中 🚲 同时命中「开锁」和「骑行中」。如果让 ONGOING 规则先匹配，开锁信号会被当成"骑行心跳"吞掉，会话根本建立不起来。

坑二：开锁正文里带「关锁还车」

快速关锁还车~ 这四个字是提示语，不是结束事件。如果 END 规则里写 关锁还车，那么开锁的瞬间就会被判定为"行程结束"，倒计时立刻被撤销——比坑一更隐蔽，因为你完全看不到任何报错。

所以 END 规则必须带限定词

只能用 行程结束、成功关锁还车、关锁结费 这类。绝不能出现裸的 关锁 或 关锁还车。
同理，END 里也不能放 本次骑行 X 元——它在开锁的营销文案里也会命中。

坑三：判定顺序

必须是 NUDGE → END → START → ONGOING。START 一定要排在 ONGOING 前面，原因见坑一。

// 开锁（START）
开锁成功 / 解锁成功 / 已开锁 / 车锁已打开 / 开始骑行

// 关锁（END）—— 全部带限定词，避开开锁正文的"快速关锁还车"
行程结束 / 成功关锁还车 / 关锁结费 / 已为您关锁 / 待支付

04实现要点

50 分钟不能用 Handler 计时

等待期间进程大概率会被系统回收，postDelayed 一定会丢。必须交给 AlarmManager，且用 ELAPSED_REALTIME_WAKEUP（基于开机时长），不能用 RTC_WAKEUP——后者在改时间或跨时区时会算错。

重启会清空所有闹钟

这是最容易漏的一点。如果你在倒计时期间重启了手机，而没有 BootReceiver 去重算，这个提醒就永远不会来。代码里由 restore() 处理：读持久化的开锁时间，算剩余时长重新武装；如果已经过期，立即补发。

同一笔订单可能连推多条开锁通知

加 5 分钟去重窗口，避免把倒计时反复往后推。

必须留两个出口

  • 「已关锁」——万一关锁通知被系统拦了，或者你确实已经关了，点一下静音；
  • 「仍在骑行」——单次骑行超过 50 分钟（长距离、跨区）时，顺延 30 分钟。

05验证与部署

先验证解析规则

用截图里的两条原文直接喂给解析器，确认输出分别是 RideStarted 和 RideEnded，这是整个方案唯一可能出错的地方：

// 这两条必须分别返回 START / END
SignalParser.explain("开锁成功，正在骑行中 🚲\n点击返回App查看订单信息，快速关锁还车~")
// 期望 START

SignalParser.explain("行程结束，已为您关锁结费\n您已成功关锁还车，点此查看行程费。")
// 期望 END

再跑通链路

把提醒临时改成 2 分钟，扫一次车、不关锁，等它响；再扫一次、正常关锁，确认不响。

BikeSessionEngine.setRemindMinutes(this, 2)   // 调试
BikeSessionEngine.setRemindMinutes(this, 50)  // 正式

必需的系统设置

  • 通知使用权：设置 → 通知 → 通知使用权。这是唯一必需的权限，掉了整个方案就失效，国产 ROM 清理后台时可能回收它。
  • 精确闹钟（Android 12+）：特殊权限 → 闹钟和提醒。没开会降级成不精确闹钟，Doze 下可能晚十几分钟。
  • 自启动：MIUI / ColorOS 需单独打开，否则重启后闹钟不会重建。
  • 电池优化白名单：adb shell dumpsys deviceidle whitelist +com.bikeguard。
建议先跑三天只记录

把提醒关掉、只看 signal-*.jsonl，正常骑几次。确认每次都是「START 紧跟一条 END」，再打开提醒。这一步能提前发现通知被系统拦截、或文案在不同城市/版本下不一致的问题。
